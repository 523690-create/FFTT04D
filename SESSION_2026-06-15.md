## Fixes & improvements

1. **Tensor CSV cleanup (#1)** *(earlier in the session)*
   `MetaAnalyzer` no longer buries age/sex in column 1. Output columns are now
   `clip_id, source, sound_type, age, gender, health, is_cough, <21 features>`; the dead
   always‑zero `age` feature was dropped (8 DSP + 13 MFCC). Demographics are parsed from
   the recording id into their own columns.

2. **Verbose USB transfers (#4 desktop end)**
   `UsbImporter.PullResult` now carries the file list / total bytes (`humanBytes()`); the
   USB import handler logs a per‑file transfer report (names + sizes + total + source dir)
   in the results pane, shows an indeterminate progress row during the adb pull, and notes
   the ack ("phone may now offer to delete its copies").

3. **Analysis UX (#6)**
   - Progress bars for the two "featurising" passes: **Discover Codebook** and the
     **Meta‑Analysis** tensor build/distance step (were status‑text only).
   - Meta‑Analysis report is far more verbose: cough %, per‑feature raw mean/sd (the
     z‑score basis), source/health/gender tallies, distance interpretation.
   - "▶ Next steps" guidance appended to Analyze, Meta‑Analysis, Codebook and USB‑import
     reports.
   - Richer explanations in the Codebook‑K and GPU dialogs.

4. **GPU / cuFFT not detected from IDE/Gradle — FIXED (root cause)**
   The RTX GPU + CUDA were fine; `GpuFft` simply failed to **find** the bundled CUDA redist
   DLLs (`desktop/native/cuda`) when launched from `build/classes` (Android Studio /
   `:desktop:run`) rather than the fat jar. The old folder walk (4 levels, only
   `native/cuda`) never reached `desktop/native/cuda` from
   `…/build/classes/kotlin/main`, so `cudart`/`cufft` were never preloaded and jcuda's
   `JCufft` JNI died with *"Can't find dependent libraries"* → `available()=false` → bogus
   "No NVIDIA GPU" message. The `286fa81` cwd→repo‑root change compounded it.
   - **Fix:** discovery now tries **both** `native/cuda` and `desktop/native/cuda` at
     `user.dir` and up to 8 ancestors of the code location — found whether launched from the
     module dir, repo root, the fat jar, or a deep classes dir.
   - Captures the real failure reason (`GpuFft.unavailableReason()`) and surfaces it in the
     CWT‑GPU dialog instead of always blaming missing hardware.
   - **Verified under Java 8** from both the fat jar and the classes dir: device count 1,
     "NVIDIA GeForce RTX 4060 Ti", cuFFT self‑test passes.
   - Optional override: set `FFTT04D_CUDA_DIR` to `desktop\native\cuda` to force the folder.
